# 游客端可售内容查询接口说明

对应的 OpenAPI 文件：[catalog-openapi.json](../接口json/catalog-openapi.json)。

该模块用于游客端首页和景点预约页，当前 MVP 提供可预约景点列表、景点详情、附近景点和按日期查询可展示场次等只读接口。票种随场次一起返回，不再单独提供游客端票种列表或场次详情接口。

## 通用业务规则

- 查询接口允许未登录用户访问，游客只在维护参观人、创建订单等操作时登录。
- 只展示状态为 `ENABLED` 的景点，不向游客暴露停用景点。
- “可展示场次”必须处于 `OPEN` 状态、预约尚未结束，并至少配置一个仍可展示的票种。
- 未到 `bookingStartAt` 的场次返回时间、价格和票种规则等静态资料，不返回剩余容量；开售后再返回动态库存。
- 已经开售但库存为 `0` 的场次仍然返回，并通过 `SOLD_OUT` 状态明确展示已售罄。
- 场次下只返回状态为 `ON_SALE` 且基础票种仍为 `ENABLED` 的票种。
- 游客端实际展示和下单计价使用 `session_ticket_type.sale_price`，不使用 `ticket_type.base_price`。
- 返回的 `sessionTicketTypeId` 是创建订单时提交的票种配置 ID。
- 返回的剩余数量只是查询时快照，不能代替创建订单时的原子库存校验。
- 数据库保存的是景点封面 `coverObjectKey`；接口只返回后端转换后的 `coverUrl`，不暴露对象键。
- 景点详情及场次票种静态快照使用 `Caffeine -> Redis -> MySQL` 两级缓存；场次动态库存不进入 Caffeine。
- 附近景点使用 Redis GEO 保存启用景点的 ID 和坐标，景点展示资料复用 `Caffeine -> Redis -> MySQL` 两级缓存。
- 附近结果按距离从近到远排列，只返回坐标完整且状态为 `ENABLED` 的景点。
- 景点坐标、游客定位坐标和地图地理编码结果必须使用同一种坐标系，否则距离会产生偏移。

## 1. 分页查询可预约景点

```http
GET /public/venues?page=1&size=20&keyword=科技馆
```

用于游客端首页的“可预约景点”列表。

查询参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `page` | 否 | 页码，默认 `1` |
| `size` | 否 | 每页数量，默认 `20`，最大 `100` |
| `keyword` | 否 | 按景点名称或地址模糊搜索，最大 100 个字符 |

业务规则：

- 只返回至少存在一个当前可售场次和可售票种的启用景点。
- `minimumPrice` 是该景点当前所有可售场次票种中的最低实际售价，仅用于“XX 元起”的列表展示。
- 建议按照最近可售场次的参观日期升序排列，同日期下按景点 ID 升序，保证分页顺序稳定。
- 搜索无结果时返回成功响应和空列表。

响应中的列表项包含：`id`、`name`、`address`、`description`、`coverUrl`、`minimumPrice`。

响应示例：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "items": [
      {
        "id": 10,
        "name": "海湾科技馆",
        "address": "广州市番禺区海湾大道 88 号",
        "description": "面向公众开放的综合性科技文化场馆。",
        "coverUrl": "https://example.com/venue-cover.jpg",
        "minimumPrice": 0.00
      }
    ],
    "total": 1,
    "page": 1,
    "size": 20
  }
}
```

## 2. 获取景点详情

```http
GET /public/venues/{venueId}
```

用于进入景点预约页时展示景点名称、地址、简介和封面。

业务规则：

- 只允许查询 `ENABLED` 景点。
- 景点不存在或已经停用时统一返回 `NOT_FOUND`。
- 景点在列表展示后可能暂时售罄；此时详情仍可正常返回，场次查询返回空列表。
- 当前表结构没有独立的城市和固定开放时间字段，因此 MVP 响应不提供 `city`、`openingHours`，前端不要写死为接口字段。

响应示例：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "id": 10,
    "name": "海湾科技馆",
    "address": "广州市番禺区海湾大道 88 号",
    "description": "面向公众开放的综合性科技文化场馆。",
    "coverUrl": "https://example.com/venue-cover.jpg"
  }
}
```

## 3. 根据当前坐标查询附近景点

```http
GET /public/venues/nearby?longitude=113.3245&latitude=23.1067&radiusKm=5&limit=20
```

查询参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `longitude` | 是 | 查询中心经度，范围 `-180 ~ 180` |
| `latitude` | 是 | 查询中心纬度，范围 `-90 ~ 90` |
| `radiusKm` | 否 | 搜索半径，默认 `5` 公里，范围 `0.1 ~ 50` |
| `limit` | 否 | 最大返回数量，默认 `20`，最大 `100` |

业务规则：

- Redis GEO 按距离升序返回景点 ID，再通过景点详情两级缓存补充展示资料。
- 不做传统分页，只限制本次最多返回多少条，符合附近搜索的 MVP 使用方式。
- 没有符合条件的景点时返回成功响应和空数组。

## 4. 根据地点名称查询附近景点

```http
GET /public/venues/nearby/by-name?name=广州塔&city=广州&radiusKm=5&limit=20
```

该接口先通过高德地理编码 Web 服务把地点名称转换为经纬度，再复用第 3 个接口对应的坐标查询 Service。

成功解析的“城市 + 地点名称”坐标会在 Redis 中缓存 7 天；相同地点再次查询时直接复用坐标，不重复调用高德接口。解析失败的结果不缓存。

| 参数 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 地点名称或地址，最大 100 个字符 |
| `city` | 否 | 限定城市，减少同名地点歧义 |
| `radiusKm` | 否 | 搜索半径，默认 `5` 公里，范围 `0.1 ~ 50` |
| `limit` | 否 | 最大返回数量，默认 `20`，最大 `100` |

使用前需要设置环境变量 `AMAP_WEB_SERVICE_KEY`。地点无法解析或高德返回业务失败时，接口返回 `INVALID_REQUEST`。

附近景点响应项包含：`id`、`name`、`address`、`description`、`coverUrl`、`distanceKm`。

## 5. 按日期查询可展示场次

```http
GET /public/venues/{venueId}/sessions?visitDate=2026-08-03
```

用于游客选择参观日期后加载当天已经发布的场次和票种。`visitDate` 必填，不能早于当前日期。

业务规则：

- 景点必须存在且处于 `ENABLED` 状态，否则返回 `NOT_FOUND`。
- 返回预约尚未结束的 `OPEN` 场次，并按开始时间升序排列。
- 未开售场次的 `saleState` 为 `NOT_STARTED`，只返回静态资料，不返回 `remainingCapacity` 和 `remainingQuantity`。
- 开售后有库存时 `saleState` 为 `ON_SALE`；场次容量或全部票种库存耗尽时为 `SOLD_OUT`。
- 每个票种固定返回名称、说明、适用人群和实际售价，开售后才附带剩余数量。
- `remainingCapacity` 限制该场次订单可占用的总人数，`remainingQuantity` 限制对应票种可购买数量；创建订单时两者必须再次校验。
- 当天没有可展示场次时返回成功响应和空数组，不返回 `NOT_FOUND`。

响应示例：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": [
    {
      "id": 21,
      "visitDate": "2026-08-03",
      "startTime": "09:00:00",
      "endTime": "11:00:00",
      "bookingStartAt": "2026-08-01T10:00:00",
      "bookingEndAt": "2026-08-03T08:30:00",
      "saleState": "ON_SALE",
      "remainingCapacity": 24,
      "ticketTypes": [
        {
          "sessionTicketTypeId": 301,
          "ticketTypeName": "成人票",
          "description": "普通参观票",
          "audienceRule": "普通成年游客",
          "salePrice": 60.00,
          "remainingQuantity": 20
        },
        {
          "sessionTicketTypeId": 302,
          "ticketTypeName": "儿童票",
          "description": "儿童优惠票",
          "audienceRule": "1.2 米以下儿童",
          "salePrice": 0.00,
          "remainingQuantity": 4
        }
      ]
    }
  ]
}
```

尚未开售时，响应仍包含场次和票种静态资料，但不会包含动态库存字段：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": [
    {
      "id": 22,
      "visitDate": "2026-08-10",
      "startTime": "09:00:00",
      "endTime": "11:00:00",
      "bookingStartAt": "2026-08-08T10:00:00",
      "bookingEndAt": "2026-08-10T08:30:00",
      "saleState": "NOT_STARTED",
      "ticketTypes": [
        {
          "sessionTicketTypeId": 303,
          "ticketTypeName": "成人票",
          "description": "普通参观票",
          "audienceRule": "普通成年游客",
          "salePrice": 60.00
        }
      ]
    }
  ]
}
```

## 与创建订单接口的衔接

游客选定场次、票种和参观人后，调用现有的 `POST /tourist/orders`：

```json
{
  "sessionId": 21,
  "items": [
    {
      "visitorId": 101,
      "sessionTicketTypeId": 301
    }
  ]
}
```

前端可以用查询结果展示价格和剩余数量，但订单金额、票种归属及最终库存仍由创建订单接口重新校验，不能信任前端缓存值。

## 实现时需要同步的配置

当前 JWT 过滤器默认拦截除白名单外的所有请求。实现这些公开查询接口时，需要将 `/public/**` 加入 `security.jwt.excluded-paths`，并且不要添加游客角色限制。

## MVP 暂不提供

- 热门推荐、复杂筛选和附近结果的传统分页。
- 城市、分类、标签、营业时间等当前表结构尚未支持的筛选条件。
- 独立的可售票种接口、场次详情接口和库存推送。
- 收藏、评价、浏览历史、个性化价格和优惠活动。
