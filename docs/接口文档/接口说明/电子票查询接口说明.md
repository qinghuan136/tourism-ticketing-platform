# 电子票查询接口说明

对应的 OpenAPI 文件：[ticket-openapi.json](../接口json/ticket-openapi.json)。

电子票由订单支付成功后按订单明细生成，一位参观人对应一张票。当前 MVP 只提供游客查询本人票券列表和详情的接口，不提供票券修改或删除。

## 通用业务规则

- 所有接口均要求游客登录，`userId` 从 JWT 登录信息获取，前端不传递。
- 游客只能查询自己订单生成的票券；票券不存在或不属于当前游客时统一返回 `NOT_FOUND`。
- `ticketCode` 是实际核销凭证，只通过登录后的本人票券接口返回。
- 后端返回票码字符串，二维码由前端根据 `ticketCode` 生成，不单独提供二维码图片接口。
- 一张票券对应一个订单明细，因此同时对应一个参观人、一种票和一个场次。
- 票券状态：`VALID` 有效、`REFUNDING` 退款冻结、`USED` 已核销、`VOID` 已作废、`EXPIRED` 已过期。
- 退款后票券变为 `VOID`；核销成功后变为 `USED`；场次结束后仍未使用的有效票券由后台任务变为 `EXPIRED`。

## 1. 分页查询我的票券

```http
GET /tourist/tickets?page=1&size=20&status=VALID
Authorization: Bearer <token>
```

查询参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `page` | 否 | 页码，默认 `1` |
| `size` | 否 | 每页数量，默认 `20`，最大 `100` |
| `status` | 否 | 票券状态，不传时查询全部状态 |

业务规则：

- 只查询当前游客订单生成的票券。
- 按票券有效开始时间倒序、票券 ID 倒序排列，保证分页顺序稳定。
- 每条记录返回票码、状态、景点、参观日期、场次时间、参观人和票种名称，满足“我的票券”卡片展示。
- 查询无结果时返回成功响应和空列表。

响应示例：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "items": [
      {
        "id": 701,
        "ticketCode": "TK-A8F29X2",
        "status": "VALID",
        "venueName": "海湾科技馆",
        "visitDate": "2026-08-03",
        "startTime": "09:00:00",
        "endTime": "11:00:00",
        "visitorName": "张三",
        "ticketTypeName": "成人票",
        "validFrom": "2026-08-03T09:00:00",
        "validUntil": "2026-08-03T11:00:00"
      }
    ],
    "total": 1,
    "page": 1,
    "size": 20
  }
}
```

## 2. 获取我的票券详情

```http
GET /tourist/tickets/{ticketId}
Authorization: Bearer <token>
```

用于打开票码弹窗或电子票详情页。除列表字段外，还返回订单、景点地址和成功核销时间。

响应示例：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "id": 701,
    "ticketCode": "TK-A8F29X2",
    "status": "USED",
    "orderId": 501,
    "orderNo": "202608010001",
    "venueId": 10,
    "venueName": "海湾科技馆",
    "venueAddress": "广州市番禺区海湾大道 88 号",
    "visitorId": 101,
    "visitorName": "张三",
    "ticketTypeName": "成人票",
    "visitDate": "2026-08-03",
    "startTime": "09:00:00",
    "endTime": "11:00:00",
    "validFrom": "2026-08-03T09:00:00",
    "validUntil": "2026-08-03T11:00:00",
    "verifiedAt": "2026-08-03T09:15:20"
  }
}
```

业务规则：

- 查询必须同时使用 `ticketId` 和当前游客 `userId` 限制数据范围，不能先查询后只在 Controller 判断归属。
- 不返回参观人的证件号码和手机号，电子票展示不需要这些敏感字段。
- `verifiedAt` 仅在成功核销后存在。

## MVP 暂不提供

- 票券转赠、改签、补发、删除和手工修改状态。
- 二维码图片生成、动态二维码和离线票包。
- 独立的票券退款接口；退款仍由订单整单退款接口处理。
- 游客查询核销失败记录；失败记录只在运营端核销记录中查看。
