# 工作人员管理接口

所有接口仅允许当前景点的运营者访问，工作人员的 `venueId` 和 `STAFF` 角色由后端写入或校验。

## 新建工作人员

- 方法与路径：`POST /operator/staff`
- 必填字段：`loginName`、`password`、`displayName`、`phone`。
- 登录名或手机号已存在时返回 `CONFLICT`；新账号固定为 `ACTIVE`。

## 分页查询工作人员

- 方法与路径：`GET /operator/staff/page?page=1&pageSize=20&keyword=张`
- 只返回当前景点的 `STAFF` 账号。

## 修改工作人员状态

- 方法与路径：`POST /operator/staff/status/{status}?id={staffId}`
- `status` 为 `ACTIVE` 或 `DISABLED`。
- 停用后，工作人员已经签发的 JWT 也会立即失效；重新启用后可以再次登录。

## 修改工作人员资料

- 方法与路径：`PUT /operator/staff/{staffId}`
- 身份要求：当前登录用户必须为景点运营者。
- 可修改字段：工作人员姓名、手机号。

请求示例：

```json
{
  "displayName": "张敏",
  "phone": "13800138000"
}
```

接口会限制目标账号为当前运营者所属景点的 `STAFF` 账号；登录账号、密码、角色、状态和所属景点不能通过此接口修改。

## 重置工作人员密码

- 方法与路径：`PUT /operator/staff/{staffId}/password`
- 请求体：`{"password":"<新密码>"}`。
- 只能重置当前景点工作人员的密码，密码仍按项目现有的 MD5 规则保存。
