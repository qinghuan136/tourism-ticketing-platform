# 数据库表结构设计

## 总体设计约定

- 数据库：MySQL
- 存储引擎：InnoDB
- 字符集：utf8mb4
- 主键：`BIGINT UNSIGNED AUTO_INCREMENT`
- 金额：`DECIMAL(10,2)`
- 日期时间：`DATETIME`
- 状态字段：`VARCHAR(20)`
- 所有核心业务表保留 `created_at`、`updated_at`
- 订单、订单明细、票券、核销记录等历史凭证不物理删除

---

## 核心关系概览

```text
venue（景点）
├── 1:N user_account（1个运营者账号+多个工作人员）
├── 1:N admission_session（预约场次）
├── 1:N ticket_type（票种）
├── 1:N coupon_activity（优惠券活动）
└── 1:N venue_comment（游客评论）

admission_session
└── N:M ticket_type
    └── 通过 session_ticket_type 关联

user_account（游客）
├── 1:N visitor（参观人）
├── 1:N booking_order（订单）
├── 1:N user_coupon（已领取优惠券）
├── 1:N venue_comment（发表的评论）
└── N:M venue_comment（通过 venue_comment_like 点赞）

booking_order
└── 1:N booking_order_item（订单明细：一个参观人选择一种票）

booking_order_item
└── 0..1:1 ticket（支付成功后生成票券）

ticket
└── 1:N verification_record（核销尝试记录）
```

---

# 4. 表结构设计

## 4.1 景点表 `venue`

保存景点或文旅场馆的基本信息。

| 字段名 | 类型 | 约束 | 注释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK，自增 | 景点ID |
| `name` | VARCHAR(100) | NOT NULL | 景点名称 |
| `address` | VARCHAR(255) | NOT NULL | 景点地址 |
| `description` | TEXT | NULL | 景点简介 |
| `cover_url` | VARCHAR(500) | NULL | 封面图片地址 |
| `status` | VARCHAR(20) | NOT NULL，默认 `ENABLED` | 景点状态 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | 最后修改时间 |

### 表内规则

- `status` 可取：`ENABLED`、`DISABLED`
- 建议唯一约束：`UNIQUE(name, address)`
- 景点停用后不能创建新场次或接受新订单
- 景点原则上不物理删除

### 表间关系

- 一个景点可以拥有多个运营者和工作人员
- 一个景点可以创建多个预约场次
- 一个景点可以定义多个票种

---

## 4.2 用户账号表 `user_account`

保存游客、运营者、工作人员和系统管理员账号。

| 字段名 | 类型 | 约束 | 注释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK，自增 | 用户ID |
| `login_name` | VARCHAR(50) | NOT NULL，UNIQUE | 登录名 |
| `password_hash` | VARCHAR(255) | NOT NULL | 加密后的密码 |
| `display_name` | VARCHAR(50) | NOT NULL | 用户显示名称 |
| `phone` | VARCHAR(20) | NULL，UNIQUE | 手机号 |
| `role_code` | VARCHAR(20) | NOT NULL | 用户角色 |
| `venue_id` | BIGINT UNSIGNED | NULL，FK | 所属景点ID |
| `status` | VARCHAR(20) | NOT NULL，默认 `ACTIVE` | 账号状态 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | 最后修改时间 |

### 表内规则

`role_code` 可取：

- `TOURIST`：游客
- `OPERATOR`：景点运营者
- `STAFF`：核销工作人员
- `ADMIN`：系统管理员

`status` 可取：

- `ACTIVE`
- `DISABLED`

**用户创建规则**

```text
STAFF账户由OPERATOR创建
OPERATOR账户和venue由ADMIN创建，景点运营者需要联系管理员，管理员创建景点并分配唯一的OPERATOR账号。（暂定为这样，降低系统和表的复杂度，如有需要后期再修改）

```

### 表间关系

- `venue_id` 外键指向 `venue.id`
- `OPERATOR`、`STAFF` 必须绑定景点
- `TOURIST`、`ADMIN` 的 `venue_id` 应为空
- 角色与景点的组合规则由 Service 层校验
- 游客可以维护多个参观人并创建多个订单

---

## 4.3 参观人表 `visitor`

保存游客维护的实际入场人员信息。

| 字段名 | 类型 | 约束 | 注释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK，自增 | 参观人ID |
| `user_id` | BIGINT UNSIGNED | NOT NULL，FK | 所属游客账号ID |
| `name` | VARCHAR(50) | NOT NULL | 真实姓名 |
| `id_type` | VARCHAR(20) | NOT NULL | 证件类型 |
| `id_number` | VARCHAR(64) | NOT NULL | 证件号码 |
| `phone` | VARCHAR(20) | NULL | 联系电话 |
| `status` | VARCHAR(20) | NOT NULL，默认 `ACTIVE` | 参观人状态 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | 最后修改时间 |

### 表内规则

- 建议唯一约束：`UNIQUE(user_id, id_type, id_number)`
- `status` 可取：`ACTIVE`、`DISABLED`
- 已产生历史订单的参观人不物理删除，只允许停用
- 证件号属于敏感信息，接口展示和日志记录时必须脱敏

### 表间关系

- `user_id` 外键指向 `user_account.id`
- 只有所属游客本人可以使用或修改该参观人
- 订单创建时，参观人信息会写入订单明细并保存快照

---

## 4.4 预约场次表 `admission_session`

表示某景点在特定日期和时间段提供的一批共享入场容量。

| 字段名 | 类型 | 约束 | 注释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK，自增 | 场次ID |
| `venue_id` | BIGINT UNSIGNED | NOT NULL，FK | 所属景点ID |
| `visit_date` | DATE | NOT NULL | 参观日期 |
| `start_time` | TIME | NOT NULL | 入场时段开始时间 |
| `end_time` | TIME | NOT NULL | 入场时段结束时间 |
| `booking_start_at` | DATETIME | NOT NULL | 开始预约时间 |
| `booking_end_at` | DATETIME | NOT NULL | 停止预约时间 |
| `total_capacity` | INT UNSIGNED | NOT NULL | 场次总容量 |
| `remaining_capacity` | INT UNSIGNED | NOT NULL | 场次剩余容量 |
| `status` | VARCHAR(20) | NOT NULL，默认 `DRAFT` | 场次状态 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | 最后修改时间 |

### 表内规则

- `start_time < end_time`
- `booking_start_at < booking_end_at`
- `total_capacity > 0`
- `0 <= remaining_capacity <= total_capacity`
- 建议唯一约束：`UNIQUE(venue_id, visit_date, start_time, end_time)`
- 建议查询索引：`INDEX(venue_id, visit_date, status)`

`status` 可取：

- `DRAFT`：草稿
- `OPEN`：可预约
- `CLOSED`：停止预约
- `ENDED`：已结束
- `CANCELLED`：已取消

### 表间关系

- `venue_id` 外键指向 `venue.id`
- 一个场次可以配置多个可售票种
- `total_capacity` 是场次接待人数的硬上限
- 每个场次票种拥有运营者分配的独立数量，所有分配数量之和不能超过 `total_capacity`
- 每次下单同时扣减场次 `remaining_capacity` 和对应票种的 `remaining_quantity`
- 场次本身不保存票名和价格

---

## 4.5 票种表 `ticket_type`

定义某景点可以提供的票务类型，例如成人票、学生票、儿童票。

| 字段名 | 类型 | 约束 | 注释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK，自增 | 票种ID |
| `venue_id` | BIGINT UNSIGNED | NOT NULL，FK | 所属景点ID |
| `name` | VARCHAR(100) | NOT NULL | 票种名称 |
| `description` | VARCHAR(500) | NULL | 票种说明 |
| `audience_rule` | VARCHAR(500) | NULL | 适用人群规则说明 |
| `base_price` | DECIMAL(10,2) | NOT NULL，默认 0.00 | 基础价格 |
| `status` | VARCHAR(20) | NOT NULL，默认 `ENABLED` | 票种状态 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | 最后修改时间 |

### 表内规则

- `base_price >= 0`
- 建议唯一约束：`UNIQUE(venue_id, name)`
- `status` 可取：`ENABLED`、`DISABLED`
- 票种只描述“卖什么”，不负责日期、时间和库存

### 表间关系

- `venue_id` 外键指向 `venue.id`
- 同一个票种可以配置到多个场次
- 票种停用后不能继续绑定到新场次
- 已被历史订单使用的票种不能物理删除

---

## 4.6 场次票种关联表 `session_ticket_type`

定义某个场次实际出售哪些票种、实际售价以及运营者为各票种分配的数量。

| 字段名 | 类型 | 约束 | 注释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK，自增 | 场次票种配置ID |
| `session_id` | BIGINT UNSIGNED | NOT NULL，FK | 场次ID |
| `ticket_type_id` | BIGINT UNSIGNED | NOT NULL，FK | 票种ID |
| `sale_price` | DECIMAL(10,2) | NOT NULL | 该场次实际售价 |
| `allocated_quantity` | INT UNSIGNED | NOT NULL | 该场次为票种分配的总数量 |
| `remaining_quantity` | INT UNSIGNED | NOT NULL | 该场次票种剩余可售数量 |
| `status` | VARCHAR(20) | NOT NULL，默认 `ON_SALE` | 销售状态 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | 最后修改时间 |

### 表内规则

- `sale_price >= 0`
- `allocated_quantity >= 0`
- `0 <= remaining_quantity <= allocated_quantity`
- 同一场次所有票种的 `allocated_quantity` 之和不能超过场次 `total_capacity`
- 唯一约束：`UNIQUE(session_id, ticket_type_id)`
- `status` 可取：`ON_SALE`、`OFF_SALE`
- 创建场次票种配置时，`remaining_quantity` 初始化为 `allocated_quantity`

### 表间关系

- `session_id` 外键指向 `admission_session.id`
- `ticket_type_id` 外键指向 `ticket_type.id`
- 场次和票种必须属于同一个景点
- 每个票种只能消耗自身的 `remaining_quantity`，不会自动占用其他票种配额
- 每次售票仍需同时消耗场次的统一 `remaining_capacity`，保证总人数不超过场次容量
- `sale_price` 是该场次的实际价格，可以覆盖票种的 `base_price`

---

## 4.7 订单表 `booking_order`

保存一次预约或购票行为的订单头信息。

| 字段名 | 类型 | 约束 | 注释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK，自增 | 订单ID |
| `order_no` | VARCHAR(32) | NOT NULL，UNIQUE | 业务订单号 |
| `user_id` | BIGINT UNSIGNED | NOT NULL，FK | 下单游客ID |
| `session_id` | BIGINT UNSIGNED | NOT NULL，FK | 预约场次ID |
| `quantity` | INT UNSIGNED | NOT NULL | 订单票券数量 |
| `user_coupon_id` | BIGINT UNSIGNED | NULL，FK | 本单使用的游客优惠券 |
| `original_amount` | DECIMAL(10,2) | NOT NULL | 优惠前金额 |
| `discount_amount` | DECIMAL(10,2) | NOT NULL，默认 0 | 优惠金额 |
| `total_amount` | DECIMAL(10,2) | NOT NULL | 最终应付金额 |
| `status` | VARCHAR(30) | NOT NULL | 订单状态 |
| `payment_no` | VARCHAR(64) | NULL，UNIQUE | 模拟支付流水号 |
| `refund_no` | VARCHAR(64) | NULL，UNIQUE | 商户退款单号 |
| `expire_at` | DATETIME | NULL | 支付截止时间 |
| `paid_at` | DATETIME | NULL | 支付成功时间 |
| `cancelled_at` | DATETIME | NULL | 用户取消时间 |
| `closed_at` | DATETIME | NULL | 超时关闭时间 |
| `completed_at` | DATETIME | NULL | 订单完成时间 |
| `refund_requested_at` | DATETIME | NULL | 退款申请时间 |
| `refund_at` | DATETIME | NULL | 退款时间 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | 最后修改时间 |

### 表内规则

- `quantity > 0`
- `original_amount >= 0`
- `0 <= discount_amount <= original_amount`
- `total_amount = original_amount - discount_amount`
- `quantity` 必须等于该订单的订单明细数量
- `original_amount` 必须等于所有订单明细的 `unit_price` 之和
- 订单金额由后端计算，不能直接采用前端传入金额
- 建议索引：`INDEX(user_id, created_at)`
- 建议索引：`INDEX(session_id, status)`
- 建议索引：`INDEX(user_coupon_id)`
- 退款对账索引：`INDEX(status, refund_requested_at)`

`status` 可取：

- `PENDING_PAYMENT`：待支付
- `PAID`：已支付/预约有效
- `REFUNDING`：退款处理中
- `CANCELLED`：用户取消
- `CLOSED`：超时关闭
- `COMPLETED`：已完成
- `REFUNDED`：已退款

### 表间关系

- `user_id` 外键指向 `user_account.id`
- `session_id` 外键指向 `admission_session.id`
- `user_coupon_id` 外键指向 `user_coupon.id`，为空表示本单未使用优惠券
- 一个订单只对应一个场次
- 一个订单可以包含多个订单明细
- 待支付订单通过订单明细保存已选择的参观人和票种

优惠券活动、异步领取请求和游客优惠券三张表的详细字段及 Redis/Kafka 规则，见 [优惠券秒杀业务与表设计](优惠券秒杀业务与表设计.md)。

## 4.8 订单明细表 `booking_order_item`

保存订单中的每一位参观人、所选票种和下单价格。订单创建时立即写入，不等待支付成功。

| 字段名 | 类型 | 约束 | 注释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK，自增 | 订单明细ID |
| `order_id` | BIGINT UNSIGNED | NOT NULL，FK | 所属订单ID |
| `visitor_id` | BIGINT UNSIGNED | NOT NULL，FK | 参观人ID |
| `session_ticket_type_id` | BIGINT UNSIGNED | NOT NULL，FK | 所选场次票种配置ID |
| `visitor_name` | VARCHAR(50) | NOT NULL | 下单时参观人姓名快照 |
| `visitor_id_type` | VARCHAR(20) | NOT NULL | 下单时证件类型快照 |
| `visitor_id_number` | VARCHAR(64) | NOT NULL | 下单时证件号快照 |
| `ticket_type_name` | VARCHAR(100) | NOT NULL | 下单时票种名称快照 |
| `unit_price` | DECIMAL(10,2) | NOT NULL | 下单时单价快照 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |

### 表内规则

- `unit_price >= 0`
- 唯一约束：`UNIQUE(order_id, visitor_id)`
- 一个参观人在同一订单中只能出现一次
- 快照字段创建后原则上不再修改
- 即使用户之后修改参观人信息或票种名称，历史订单仍保留原始内容

### 表间关系

- `order_id` 外键指向 `booking_order.id`
- `visitor_id` 外键指向 `visitor.id`
- `session_ticket_type_id` 外键指向 `session_ticket_type.id`
- 参观人必须属于订单的下单用户
- 所选场次票种必须属于订单对应的场次
- 支付成功后，每条订单明细生成一张票券

## 4.9 电子票券表 `ticket`

保存支付成功后生成的独立入场凭证。

| 字段名 | 类型 | 约束 | 注释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK，自增 | 票券ID |
| `ticket_code` | VARCHAR(64) | NOT NULL，UNIQUE | 唯一票码 |
| `order_item_id` | BIGINT UNSIGNED | NOT NULL，UNIQUE，FK | 对应订单明细ID |
| `status` | VARCHAR(20) | NOT NULL，默认 `VALID` | 票券状态 |
| `valid_from` | DATETIME | NOT NULL | 开始有效时间 |
| `valid_until` | DATETIME | NOT NULL | 失效时间 |
| `verified_at` | DATETIME | NULL | 成功核销时间 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | 最后修改时间 |

### 表内规则

- `valid_from < valid_until`
- `order_item_id` 唯一，保证一条订单明细最多生成一张票
- `ticket_code` 必须全局唯一
- 票券不能物理删除

`status` 可取：

- `VALID`：有效
- `REFUNDING`：退款处理中，暂停核销
- `USED`：已核销
- `VOID`：已作废
- `EXPIRED`：已过期

### 表间关系

- `order_item_id` 外键指向 `booking_order_item.id`
- 只有订单支付成功后才能生成票券
- 一张票券对应一个参观人和一种票
- 参观人、场次、票种信息通过订单明细追溯

---

## 4.10 核销记录表 `verification_record`

保存每一次核销请求，包括成功和失败记录。

| 字段名 | 类型 | 约束 | 注释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK，自增 | 核销记录ID |
| `request_no` | VARCHAR(64) | NOT NULL，UNIQUE | 核销请求号 |
| `ticket_id` | BIGINT UNSIGNED | NOT NULL，FK | 被核销票券ID |
| `verifier_id` | BIGINT UNSIGNED | NOT NULL，FK | 核销工作人员ID |
| `result` | VARCHAR(20) | NOT NULL | 核销结果 |
| `failure_reason` | VARCHAR(255) | NULL | 核销失败原因 |
| `device_no` | VARCHAR(64) | NULL | 模拟核销设备编号 |
| `verified_at` | DATETIME | NOT NULL | 核销请求时间 |

### 表内规则

- `request_no` 全局唯一，用于保证同一次核销请求幂等
- `result` 可取：`SUCCESS`、`FAILED`
- 成功记录的 `failure_reason` 应为空
- 失败记录应填写可识别的失败原因

### 表间关系

- `ticket_id` 外键指向 `ticket.id`
- `verifier_id` 外键指向 `user_account.id`
- 核销人员所属景点必须与票券对应场次所属景点一致
- 一张票券可以有多条失败记录，但只能成功核销一次

---

## 4.11 景点评论表 `venue_comment`

保存游客对景点发表的基础评论，不支持跟评。

| 字段名 | 类型 | 约束 | 注释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK，自增 | 评论ID |
| `venue_id` | BIGINT UNSIGNED | NOT NULL，FK | 所属景点ID |
| `user_id` | BIGINT UNSIGNED | NOT NULL，FK | 评论游客ID |
| `content` | VARCHAR(500) | NOT NULL | 评论内容 |
| `like_count` | INT UNSIGNED | NOT NULL，默认 `0` | 点赞数量 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | 最后修改时间 |

### 表内规则

- 评论列表按 `like_count DESC, id DESC` 排序。
- `like_count` 是列表排序使用的冗余计数，由点赞事务同步维护。
- 景点和用户账号均不物理删除，评论保留历史记录。

## 4.12 评论点赞表 `venue_comment_like`

保存游客的评论点赞关系。

| 字段名 | 类型 | 约束 | 注释 |
|---|---|---|---|
| `comment_id` | BIGINT UNSIGNED | PK，FK | 评论ID |
| `user_id` | BIGINT UNSIGNED | PK，FK | 点赞游客ID |
| `created_at` | DATETIME | NOT NULL | 点赞时间 |

### 表内规则

- 联合主键 `PRIMARY KEY(comment_id, user_id)` 保证同一游客只能点赞同一评论一次。
- 点赞记录插入成功时，评论表的 `like_count` 加一；删除成功时减一。
