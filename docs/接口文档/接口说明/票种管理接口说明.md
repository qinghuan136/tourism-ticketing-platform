# 票种管理接口说明

对应的 OpenAPI 文件：[tickettype-openapi.json](../接口json/tickettype-openapi.json)。

当前 MVP 提供当前景点票种的分页查询、详情、新建、修改和批量删除接口。所有接口仅允许景点运营者访问，景点 ID 从 JWT 登录信息中的 `venueId` 获取，前端不传递 `venueId`。

## 通用业务规则

- 所有查询和写操作都必须限定在当前运营者所属景点内，不能查看或修改其他景点的票种。
- 同一景点内票种名称不能重复；不同景点可以使用相同票种名称。
- 基础价格必须大于等于 `0`，数据库按两位小数保存。
- `basePrice` 是票种的参考基础价格。场次绑定票种后，实际售价保存在 `session_ticket_type.sale_price` 中；修改基础价格不会追溯修改已有场次售价和历史订单金额。
- 状态只有 `ENABLED` 和 `DISABLED`。停用票种后不能再绑定到新场次，但不会删除已有场次配置或历史订单。

## 分页查询票种

```http
GET /operator/ticket-types?page=1&size=20&keyword=学生
Authorization: Bearer <token>
```

用于票种管理列表。`keyword` 可选，按票种名称模糊查询；`page` 默认 `1`，`size` 默认 `20`，最大 `100`。查询结果按创建时间倒序排列。

只返回当前景点的票种，不接受前端传入景点 ID。

## 获取票种详情

```http
GET /operator/ticket-types/{ticketTypeId}
Authorization: Bearer <token>
```

用于打开编辑表单时加载完整票种资料。目标票种不存在或不属于当前景点时统一返回 `NOT_FOUND`，避免泄露其他景点的数据。

## 新建票种

```http
POST /operator/ticket-types
Authorization: Bearer <token>
Content-Type: application/json
```

请求示例：

```json
{
  "name": "学生票",
  "description": "面向全日制在校学生",
  "audienceRule": "入场时须出示有效学生证",
  "basePrice": 30.00,
  "status": "ENABLED"
}
```

业务规则：

- `name`、`basePrice` 和 `status` 必填。
- `venueId` 由后端从当前登录用户中写入。
- 同一景点已有相同名称时返回 `CONFLICT`。
- 创建成功后返回新票种 ID。

## 修改票种

```http
PUT /operator/ticket-types/{ticketTypeId}
Authorization: Bearer <token>
Content-Type: application/json
```

请求示例：

```json
{
  "name": "学生优惠票",
  "description": "面向全日制在校学生",
  "audienceRule": "入场时须出示本人有效学生证",
  "basePrice": 25.00,
  "status": "ENABLED"
}
```

业务规则：

- 只能修改当前景点的票种，不能修改 `venueId`。
- 修改名称时仍需满足同一景点内名称唯一。
- 修改基础价格不会级联修改 `session_ticket_type.sale_price`。
- 将状态改为 `DISABLED` 时，仅阻止后续绑定到新场次；已有场次关联和历史订单保持不变。

## 批量删除票种

```http
DELETE /operator/ticket-types?ids=1,2,3
Authorization: Bearer <token>
```

业务规则：

- `ids` 必填，使用英文逗号分隔，允许只传一个票种 ID，单次最多删除 `100` 个票种。
- 所有票种都必须存在并属于当前景点；任一票种不存在或不属于当前景点时返回 `NOT_FOUND`，本批次不删除任何数据。
- 删除前必须检查 `session_ticket_type`：只要任一票种已经被场次引用，无论关联当前是否为 `ON_SALE`，都返回 `CONFLICT`，本批次不删除任何数据。
- 该规则同时保护场次配置和通过 `session_ticket_type` 关联的历史订单明细，删除操作不做级联清理。
- 从未绑定到任何场次的票种可以直接物理删除，不要求先停用。
- 整批校验和删除必须在同一事务中完成，批量删除采用全部成功或全部失败的方式。

## MVP 范围

当前不提供批量启停、票种复制或独立的票种与场次绑定接口。场次票种绑定及场次实际售价由场次管理功能处理。
