# 运营统计接口说明

对应 OpenAPI 文件：[statistics-openapi.json](../接口json/statistics-openapi.json)。

当前 MVP 只提供经营概览、每日销售趋势和票种销售排行三个只读接口。统计范围固定为当前登录运营者所属景点，不提供跨景点统计、导出、同比或复杂图表。

## 通用规则

- 仅允许 `OPERATOR` 访问。
- `venueId` 从 JWT 登录信息获取，客户端不能自行指定。
- `startDate`、`endDate` 均为必填，格式为 `yyyy-MM-dd`，并完整包含结束日期当天。
- 统计使用左闭右开的时间区间：`startDate 00:00:00 <= time < endDate + 1 天 00:00:00`。
- `endDate` 早于 `startDate` 时返回 `INVALID_REQUEST`。
- 三个统计接口按“景点、日期范围、统计类型”缓存 Redis 查询结果，TTL 为 60 秒；因此运营看板最多存在约一分钟的统计延迟。
- 统计结果变化频繁，当前不通过 Canal 逐次删除缓存，到期后自动重新聚合 MySQL 数据。

## 1. 查询经营概览

```http
GET /operator/statistics/overview?startDate=2026-08-01&endDate=2026-08-10
Authorization: Bearer <token>
```

返回字段：

- `paidOrderCount`：统计期内支付成功的订单数，以 `paid_at` 为准。
- `grossRevenue`：上述订单的实收金额合计，已在后续退款的订单仍计入历史实收。
- `refundAmount`：统计期内实际发生退款的金额，以 `refund_at` 为准。
- `netRevenue`：`grossRevenue - refundAmount`，表示统计期内净资金流入。
- `soldTicketCount`：统计期内支付成功订单的票券数量合计。
- `verifiedTicketCount`：统计期内成功核销的电子票数量，以 `ticket.verified_at` 为准。

## 2. 查询每日销售趋势

```http
GET /operator/statistics/trend?startDate=2026-08-01&endDate=2026-08-10
Authorization: Bearer <token>
```

按支付日期升序返回每天的 `paidOrderCount`、`grossRevenue` 和 `soldTicketCount`。没有支付订单的日期不返回记录，前端绘制连续日期图表时可以自行补零。

## 3. 查询票种销售排行

```http
GET /operator/statistics/ticket-types?startDate=2026-08-01&endDate=2026-08-10
Authorization: Bearer <token>
```

按销量从高到低返回：

- `ticketTypeName`：下单时保存的票种名称快照。
- `soldQuantity`：已支付订单中的该票种明细数量。
- `salesAmount`：明细成交单价合计。

使用订单明细快照进行聚合，因此票种后续改名或改价不会改变历史统计。当前接口统计毛销售数据，后续发生的整单退款只体现在经营概览的 `refundAmount` 中。
